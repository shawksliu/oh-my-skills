# Content → Infographic

## Why this skill exists

The default AI instinct when asked to "make an image" is to reach for dark backgrounds, neon accents, glassmorphism, gradients, and emoji — the visual equivalent of "sounds impressive but says nothing." The result looks like a SaaS dashboard, not something you'd actually save or share.

Good infographics look like editorial print — clean paper, restrained color, muscular typography, and generous whitespace. **The goal is a page that looks like it was designed by a person with taste, not generated by an AI trying to impress.**

Follow this process end to end rather than jumping straight to HTML.

---

## 1. Distill before designing

Read back over the content (the conversation, notes, or document) and extract:

- **The thesis** — the single sentence that is the core takeaway, if the content has one.
- **The shape** — is this a sequence of steps/layers, an A-vs-B comparison, a list of categories, one key fact with supporting detail, or a timeline? The shape decides the layout, not the other way around.
- **2–4 numbers or short callouts** worth pulling out on their own, if the content has any.
- **Anything that's a caveat or limitation** worth its own box, if relevant — infographics that only show the upside read as marketing, not as a summary.

Cut ruthlessly. An infographic is a distillation, not a transcript — if a detail doesn't fit cleanly into the shape you picked, leave it out and let the surrounding chat carry it instead.

## 2. Pick a layout archetype to match the shape

Don't reuse the same card-grid for everything — match the structure to the content:

| Content shape | Layout |
|---|---|
| Sequential steps / layers / a process | Numbered stacked rows with colored index markers (1, 2, 3…) |
| A vs. B comparison | Two- or three-column split panel with contrasting header badges |
| One key insight + supporting data | Large hero statement, stat row beneath |
| Timeline / chronology | Connected vertical sequence with left-aligned markers |
| Mixed (thesis + categorized detail + caveat) | Header/thesis block → content sections → callout box → stat row → footer. This is the default workhorse layout when nothing more specific fits. |

## 3. Design system — the editorial warm-tone standard

This is the most important section. It defines the visual identity that separates a good infographic from AI slop.

### 3.1 The aesthetic north star

The target aesthetic is **editorial print** — think well-typeset journal articles, design monographs, or Palantir/Stripe's annual reports. The defining qualities:

- **Warm, muted, paper-like backgrounds** — not screens, not dashboards
- **One or two restrained accent colors** — never more, never neon
- **Typography does all the heavy lifting** — size, weight, and spacing create hierarchy, not color or decoration
- **Generous whitespace** — content breathes; density comes from structure, not cramming
- **Near-zero decoration** — no gradients, no glows, no shadows, no background patterns, no glassmorphism

### 3.2 Color palette rules

Pick from this tonal family (adapt the exact hues to the content's subject, but stay within this warmth and saturation range):

| Role | Default value | Notes |
|------|---------------|-------|
| Page background | `#F5F0E8` — warm cream/parchment | The single most important choice. This is NOT white (`#fff`) and NOT grey. It is warm, soft, and papery. Alternate: `#F0EDE4` (sage cream), `#EDEBE3` (cool linen) |
| Card / section surface | `#FFFFFF` or `#FAFAF7` | Cards are white against the warm background — the contrast is subtle but clear |
| Primary text | `#2D2A26` — warm charcoal | Not pure black. Warm, not cold. Reads like ink on paper |
| Secondary text | `#6B6560` — warm mid-grey | For descriptions, captions, supporting content |
| Tertiary text | `#9C9690` — warm light grey | For metadata, footer, timestamps |
| Accent 1 (primary) | One of: `#C45A3C` (terracotta), `#5B7A5E` (olive), `#4A6B8A` (slate blue), `#8B6E4E` (saddle) | Low saturation. Used ONLY for: section numbers, kicker text, key highlighted terms, badges. Pick one per infographic and commit. |
| Accent 2 (secondary) | Optional. A muted complement to accent 1 | Used sparingly — for a single callout box background tint or a contrasting badge. If you don't need it, don't use it. |
| Border / divider | `#E0DCD4` or `#D6D2CA` | Thin (1px), warm-toned, subtle. Never dark or high-contrast borders. |

**Hard prohibitions (the AI-slop checklist):**
- ❌ Dark/black backgrounds (`#000` – `#1a1a2e` range) — this is not a dashboard
- ❌ Neon or high-saturation accents (electric blue, bright green, hot pink, AI purple)
- ❌ More than 2 accent colors in the same infographic
- ❌ Gradient fills on any element (backgrounds, cards, text, borders)
- ❌ `box-shadow` with spread or blur > 2px — if you need depth, use border only
- ❌ `backdrop-filter: blur()` / glassmorphism of any kind
- ❌ Background patterns, grid overlays, dot grids, noise textures
- ❌ `text-shadow`, `box-shadow` glow effects, `filter: drop-shadow()`
- ❌ Emoji anywhere in the design (🌱❌⚡🔍🔌💡 etc.) — use text, punctuation marks, or nothing

### 3.3 Typography system

| Role | Font | Weight | Size range | Notes |
|------|------|--------|------------|-------|
| **Headline (CJK)** | Noto Sans SC | 900 (Black) | 36–48px | The star of the show. Big, bold, unapologetic. |
| **Headline (Latin)** | Plus Jakarta Sans or Outfit | 800–900 | 36–48px | Pair with CJK — used for mixed-language titles |
| **Kicker / eyebrow** | Plus Jakarta Sans or Outfit | 700 | 12–13px | ALL CAPS, letter-spacing 1–2px. Above the main title. Colored in accent 1. |
| **Section title** | Noto Sans SC | 700 | 18–22px | Bold, not huge. |
| **Body** | Noto Sans SC | 400–500 | 13–15px | Comfortable reading size. `line-height: 1.6` |
| **Label / code / data** | JetBrains Mono or Fira Code | 400–500 | 11–13px | For technical terms, numbered badges, metadata |
| **Large number / stat** | Plus Jakarta Sans | 800–900 | 40–56px | Oversized, colored in accent, used sparingly in stat rows |

**Typography prohibitions:**
- ❌ Inter (the AI default — instantly recognizable as generated)
- ❌ Serif fonts for body text in technical content
- ❌ More than 3 font families in one infographic
- ❌ `background-clip: text` gradient text effects

### 3.4 Spacing and structure

| Element | Value |
|---------|-------|
| Canvas width | 1000–1080px fixed. No fixed height — content determines height. |
| Canvas padding | 48–60px all sides |
| Section gap | 36–48px between major sections |
| Card inner padding | 20–28px |
| Card border-radius | 8–12px max. Not 18px, not 24px. Subtle rounding, not bubble shapes. |
| Card border | 1px solid `#E0DCD4`. No shadows. |
| Grid gap (multi-column cards) | 16–20px |

### 3.5 Signature element

Every infographic gets ONE bold design choice — not five. Pick one:

- An oversized punctuation mark or glyph (a giant `?` or `→` in the thesis area)
- One inverted-color panel (accent background with white text) for the most important callout
- A thick colored left-border on the thesis/key-insight block
- Section numbers in large colored type (01, 02, 03…)
- A horizontal workflow strip with numbered steps connected by arrows at the bottom

Spend the design's personality budget there. Everything else stays disciplined.

### 3.6 Component patterns

**Numbered section cards** (most common — used in the reference designs):
```
┌──────────────────────────────────┐
│ 01                    [accent]   │  ← small colored number
│                                  │
│ Section Title          [bold]    │  ← Noto Sans SC 700, 17-18px
│                                  │
│ Description text here in warm    │  ← 13px, secondary color
│ grey, 2-3 lines max.            │
└──────────────────────────────────┘
```

**Comparison columns** (role differentiation):
```
┌──────────┐ ┌──────────┐ ┌──────────────┐
│ [label]  │ │ [label]  │ │ [accent bg]  │  ← one column gets accent treatment
│ Title    │ │ Title    │ │ Title        │
│ desc     │ │ desc     │ │ desc         │
└──────────┘ └──────────┘ └──────────────┘
```

**Stat row** (bottom of page):
```
   48                 0                  ∞
   large accent     large accent      large accent
   small label      small label       small label
```

**Callout / caveat box**:
```
┌─ accent bg tint ─────────────────────┐
│                                       │
│  [badge label]                        │
│  Bold callout text here.              │
│  Supporting details in body weight.   │
│                                       │
└───────────────────────────────────────┘
```

**Horizontal workflow strip**:
```
  ┌────┐     ┌────┐     ┌────┐     ┌────┐
  │ 01 │ →   │ 02 │ →   │ 03 │ →   │ 04 │
  │name│     │name│     │name│     │name│
  │desc│     │desc│     │desc│     │desc│
  └────┘     └────┘     └────┘     └────┘
```

## 4. Build a single self-contained HTML file

- One file, inline `<style>`, web font import via `@import url(...)` (Google Fonts).
- Fixed width canvas (`1000–1080px`), no fixed height — let content determine height, then screenshot with `fullPage` capture.
- Typical section order: kicker (small caps, accent color) + main title (big, bold) → subtitle/definition → thesis/hero block → main content sections → optional callout/caveat box → optional stat row → thin footer with metadata.
- Keep CSS selectors flat and simple — it's easy for a type-based selector and an element-based selector to cancel each other out on padding/margin, especially between sections.
- The `body` or outermost wrapper gets the warm background color. Cards/panels inside are white or near-white.

**Before writing code, state explicitly (in a code comment or to yourself):**
1. What page background color you chose
2. What accent color(s) you chose and why
3. What signature element you're using
4. What font pairing you're using

If any of these answers are "dark background", "multiple bright accents", or "glassmorphism" — stop and reconsider. You're about to produce AI slop.

## 5. Render to PNG

Use the bundled script rather than writing a new Playwright invocation each time:

```bash
node scripts/render.js <input.html> <output.png> [width]
```

`width` defaults to 1040 if omitted. This drives headless Chromium via Playwright, takes a full-page screenshot, and writes the PNG.

**Fallback** (if the bundled script fails due to missing `playwright` dependency):

```bash
npx -y playwright screenshot --viewport-size="1080,800" --full-page "file:///<absolute-path-to-html>" "<output.png>"
```

If Playwright itself is not installed, run `npx -y playwright install chromium` first.

## 6. Self-critique before presenting

View the rendered PNG (not just the HTML source) and check for:

- Text overflow or clipping, especially in fixed-width cards
- Wildly uneven content length between cards in the same row
- Orphaned single words dangling on their own line
- Low-contrast text against its background
- **Dark backgrounds, neon accents, or emoji that snuck in** — if you see any, STOP and fix before presenting
- Any element that screams "AI-generated template" — gradient text, glass panels, multiple colored glows
- Cards that feel cramped — if content is tight, increase padding or split into more cards

Iterate on the HTML — not just the copy — if something's off: adjust grid spans, cut a card, tighten a line, re-render. A picture is worth a thousand tokens; look at it before deciding it's done.

## 7. Deliver

Present the final PNG as an artifact. Keep the accompanying message short — a one-line description of what the image contains is enough; the image speaks for itself.

---

## Scope notes

This produces a static image, not an interactive artifact — reach for this skill specifically when the user wants something viewable as a picture, saveable to a camera roll, or shareable as an image, rather than an HTML/React artifact meant to be used in-browser.

It works well for any content that has internal structure to surface: an explanation, a comparison, a decision recap, a checklist, a set of stats. It works poorly for long-form prose with no real internal structure — if the content resists being distilled into one of the shapes above, say so rather than forcing it into cards that just fragment a paragraph.
